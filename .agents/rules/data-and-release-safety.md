# 保存・移行・並行処理・外部資産の保護

## 保存・移行・並行処理

- 旧ライブラリ、設定、プレイリスト、ダウンロード済みメディアの移行・再構成は原本やバックアップを保護して検証する。未知形式・破損・非互換を黙って初期化、上書き、削除しない。
- プレイリスト内の登録曲IDとメディアの同一性、動画のパート・形式、保存先を混同しない。取り込み・コピー・移動・再ダウンロードでは既存の階層、順序、参照先とユーザーの明示操作を尊重する。
- 保存・移行・取り込み・ダウンロードの確定は競合、再入、取消、失敗後の再試行を考慮する。状態が不明な場合は成功・失敗を推測せず、実際の保存内容を確認してから再実行する。
- 一時ファイルや移行元の整理時は所有者・参照元・復旧可能性を確認する。アプリが管理していないファイルや、他の登録曲が参照しているメディアを削除しない。
- 保存・移行・重複処理の検証では、正常系だけでなく競合・失敗・取消・再起動後の状態を確認する。

## 外部情報・資産・Setup/Patch

- Bilibili等の外部サービスが返す動画ID、別表記、パート、取得可否を確認済み情報と未確認情報に分ける。推測した対応情報を保存済みの正本として採用しない。
- 既存のビルド入力、SDK・ランタイム、サムネイル等の資産は実体、出典、版、必要なライセンス、復元手順、利用可能なハッシュを照合する。通常の一覧にないだけで欠落や不要と判断しない。
- 不足素材・権限・環境制限は具体的に記録し、完全性を確認せず完全ソースと報告しない。通常Git・LFS・別途保管の必要性を判断し、必要資産を黙って省かない。
- 外部の参考実装・画像・IDは権利や利用条件を確認し、無条件に流用しない。Cookie、トークン、認証情報、個人データ、機密URLをGit・レポート・診断ログ・配布物へ含めない。
- Setup・Patchでは更新対象、版、必要なファイルとハッシュ、アプリの停止、既存データ保持、失敗時の復旧を確認する。配布物の検証と利用者PCでの更新成功を区別する。
