- スマホ版そのもの、自動同期、追加・削除の自動反映、同期の競合解決は後続バージョンの対象です。
- 今回の共有は、出力・取り込みによるプレイリスト構造の受け渡しを扱います。

## 2. 実装・確認の進め方

- 全12ステップで進めます。大きすぎる工程はStep3-1などへ細分化できます。
- 各実装ステップでは変更箇所の軽量な確認を行います。
- 全体検証・全体ビルド・エラー修正は、最後から一つ前のStep11へまとめます。
- 最終Patchの生成・出力はStep12で行います。
- UIを変更したステップでは、変更後の見た目と基本操作を確認できる簡単なHTML形式などの触れるプレビューを作成します。
- プレビュー上の模擬操作と、実アプリで実装・確認済みの動作を区別します。
- 既存の設定・プレイリスト・DLデータを保持する更新とします。

## 3. 共通処理と端末ごとの処理

| 区分 | 責務 |
| --- | --- |
| 共通処理 | プレイリストの親子関係、並び順、動画識別、参照管理、検索、再生順、受け渡し用データ形式 |
| 端末ごとの処理 | ファイル保存・削除、実際のダウンロード、再生エンジン、OS連携、配布・更新 |
| UI | PC用とスマホ用を別途構築し、共通のデータと操作仕様を利用します |

今回変更する部分から段階的に分離します。スマホ実装の前にアプリ全体を一括で作り直す計画ではありません。

共通データには端末に依存しない安定した識別IDとデータ形式のバージョンを持たせます。プレイリストの所属と動画そのものの識別を分け、曲名やPCの保存パスを同一性の基準にしません。

将来の同期で追加・削除・移動を照合できる土台を用意します。同期の更新判定・削除履歴・競合解決の方式は後続バージョンで扱います。今回の取り込みを、自動的な端末間同期として扱いません。

## 4. プレイリスト出力の用途

| 出力ボタン | 主な用途 | 含める内容 |
| --- | --- | --- |
| プレイリスト情報のみ出力 | PC・スマホ間の共有 | リスト名、親子関係、並び順、楽曲名、動画リンク、パート番号、識別IDなどの構造情報 |
| DLデータを含めて出力 | PC間の共有 | 上記の情報と、保存済みの動画・音声・サムネイル |

- 情報のみの出力では、保存済みメディアを同梱せず、DL容量に左右されない軽い受け渡しを目指します。
- 同じプレイリスト階層・曲順・名称をPCと将来のスマホで再現できる形式とします。画面レイアウトそのものを共有する仕様ではありません。
- PC固有の絶対パス、ログイン情報、認証情報を構造情報に含めません。
- ローカル取り込み曲は楽曲情報を残し、メディア未同梱であることを判別できるようにします。
- 両形式とも親子関係・並び順を保持し、取り込み時に平坦なリストへ崩さない仕様とします。

## 5. 実装ステップ

### Step1：共通データ形式と責務の整理

- プレイリスト構造、動画識別、参照管理、検索、再生順などを端末非依存の処理として整理します。
- ファイル保存、ダウンロード、再生エンジン、OS連携を端末ごとの処理へ分離できる境界を定めます。
- プレイリスト・登録曲の安定したID、動画リンクの識別、データ形式のバージョン管理を整えます。
- 同じ動画リンクは複数プレイリストから共通利用します。
- URLの不要な付加情報を除き、パート番号の違いは別曲として扱います。
- av／BVの別表記は、同一動画と確認できた場合に統合します。
- 動画と音声の保存形式を区別し、曲名・プレイリスト名を識別基準にしません。
- 将来の同期と既存の出力・取り込みとのIDの扱いを整理し、同じIDの衝突や意図しない上書きを避ける仕様を定めます。

### Step2：DLデータを動画リンク単位で管理

- プレイリスト別の保存構造を、動画リンク単位の曲フォルダーへ変更します。
- 構造は概念上「downloads／動画識別子・パート／保存ファイル」とします。
- 曲ごとのフォルダーを維持し、動画・音声・サムネイルをその曲にまとめます。
- 同じ動画のDLデータを複数プレイリストから共通利用し、不要な再取得を防ぎます。
- 同じ動画への同時DL要求も重複処理しないようにします。
- 曲名変更、リスト間移動、親子構造変更でも保存位置を固定します。

### Step3：既存DLデータの移行と出力処理の分離

- v0.6.6の動画・音声・サムネイルを、再DLせず新構造へ移行します。
- 新しい保存先と管理情報の確定後に、旧ファイル・空フォルダーを整理します。
- 中断・容量不足・権限不足などで失敗しても、元のデータを失わず再開できるようにします。
- プレイリスト構造情報とメディアを分離し、情報のみ／DLデータ付きの両方を出力・取り込みできる処理を整えます。
- DLデータ付きの取り込みも、新しい動画リンク単位の保存構造へ接続します。
- 親子関係・曲順・名称・リンク・パート番号を保持します。
- PC固有の絶対パスや認証情報を構造情報へ含めません。
- ローカル取り込み曲のメディア未同梱状態を扱います。

### Step4：削除・移動時の保存データ管理

- 他プレイリストに参照が残るDLデータは保持します。
- 最後の参照を削除した場合だけ、対応する動画・音声・サムネイルを整理します。
- 曲削除、リスト削除、複数曲操作に同じ参照判定を適用します。
- 移動元と移動先の更新を一括確定し、移動途中の参照ゼロで誤削除しません。
- 再生・DL・出力などで使用中のデータは、使用終了後に参照を再確認して削除します。
- DL中に参照が削除された場合も、完了後に不要データが残り続けないようにします。
- 管理情報から確認できる既存の参照切れデータを整理します。
- アプリが管理していないファイルを一律削除しません。

### Step5：動画編集画面へ単曲DLを追加

- 「動画の編集」に「この動画のみをダウンロード」ボタンを追加します。
- 選択した動画・パートの1曲だけを対象にします。
- 既存の保存形式・画質選択、進捗表示、エラー表示へ接続します。
- 保存済みデータを再利用し、不要な再取得を防ぎます。
- DL操作で、入力途中の曲名を保存操作なしに確定させません。
- 対象選択・状態管理と、端末ごとの実際の取得・保存処理を分けます。
- 変更後の編集画面のHTMLプレビューを作成します。

### Step6：プレイリスト選択・出力UIの改善

- 追加元・追加先の一覧を、元の親子関係が分かる階層表示にします。
- 自分自身は表示を残し、選択できない状態にします。
- 自分を含む親や兄弟を隠しません。
- 選択不可の行でも、子の展開・折り畳みを操作できるようにします。
- 親変更では、自分自身や循環につながる子孫も表示したまま選択不可にします。
- 「既存のプレイリストから移動」ボタンを、「選択した曲を追加」の左側へ配置します。
- 出力画面に「プレイリスト情報のみ出力」と「DLデータを含めて出力」を追加します。
- 情報のみはPC・スマホ間、DLデータ付きはPC間の共有が主な用途であることと、同梱内容を表示します。
- 変更画面のHTMLプレビューを作成します。

### Step7：プレイリスト上限を999個へ変更

- 親・子を含む保有プレイリスト全体の上限を、100個から999個へ変更します。
- 作成だけでなく、起動時の読み込み、取り込み、複数選択などの制限を統一します。
- 曲の登録数、URLの一括入力数、検索表示件数など、別の制限とは分けて管理します。
- 上限付近のデータでも親子関係や保存情報を失わないようにします。

### Step8：再生バーの所属表示・DL状態表示

- 「保存済みから再生」の位置を、ホームから所属リストまでの経路表示へ変更します。
- 表示例は「ホーム ＞ 親リスト ＞ 所属リスト」です。
- 複数所属の場合は、現在の再生元の経路を表示します。
- 再生リストで利用する保存状態バッジを、再生バーでも共用します。
- 「動画保存済み」の表記を「DL済み」へ変更します。
- 音声のみの保存との違いも、補足表示などで確認できるようにします。
- 再生中の移動・名前変更後も、所属表示を追従させます。
- 再生バーと関連バッジのHTMLプレビューを作成します。

### Step9：ホームをプレイリスト中心のUIへ変更

- ユーザー提供の参考画像を基に、画像・リスト名・曲数を持つカード表示へ変更します。
- 通常のホームは、自分の管理するプレイリストを中心に表示します。
- 最上位リストから子リストをたどれる構成とし、親子関係を維持します。
- 子を独立した最上位リストとして重複表示しません。
- リストを開く操作と、そのリストを再生する操作を分けます。
- 999リストでも一度に大量描画しない構成にします。
- スマホ専用の見た目・レイアウトは、この工程では構築しません。
- ホームのHTMLプレビューを作成します。

### Step10：ホームから全登録曲を検索

- ホーム上部の検索で、全プレイリストの登録曲を検索します。
- 折り畳まれた子孫、全体再生から除外したリストも検索対象にします。
- 参考画像のように、サムネイル・曲名・所属経路・DL状態を一覧表示します。
- 同じ動画が複数リストにある場合も、所属先を確認できるようにします。
- 検索結果からの再生と、所属リストを開く操作に対応します。
- 検索解除でホームへ戻り、既存の階層の開閉状態を保持します。
- 検索画面のHTMLプレビューを作成します。

### Step11：全体検証・ビルド・エラー修正

- 既存機能の回帰確認と、今回追加した機能の検証をまとめて行います。
- 同一動画の共有、パート区別、保存形式区別、二重DL抑止を確認します。
- 旧配置からの移行、中断・失敗・再開、参照が残る場合の保持、最終参照削除を確認します。
- 再生・DL・出力中の削除や移動、削除後の再追加などの整合性を確認します。
- 情報のみ／DLデータ付きの両方で、親子関係・曲順・名称・リンクが復元できることを確認します。
- DLデータ付きの復元と、情報のみのメディア未同梱状態を確認します。
- 単曲DL、階層選択、選択不可の行、999個の境界、ホーム・検索・所属表示を確認します。
- 共通処理がPC専用機能へ直接依存していないことを確認します。
- バージョン表示・説明書をv0.6.7へ更新します。
- 全体ビルド、EXE構造・起動入口の検査を行い、検出した問題を修正します。
- 実機で未確認の表示・再生・通信などは、検証結果へ明記します。

### Step12：v0.6.7のPatch生成・出力

- Step11を通過したソースから、Windows用v0.6.7 Patchを生成します。
- 設定・プレイリスト・DLデータを保持して更新します。
- 保存構造の移行は、更新後のアプリが管理情報を確認して実施します。
- 更新内容・検証結果とともにPatchを出力します。
- 将来は同じリリース番号・変更履歴から端末別の配布物を生成できるよう、出力処理を整理します。
