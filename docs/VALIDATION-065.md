# 0.6.5 検証記録

## 確認対象

- コア、IPC接続、再生復旧、アーカイブ、画面のDOMモデル、保存処理の回帰検証。
- 最大3ワーカー、進捗の集約、中止・利用制限時の終了待ち。
- av/BVの同時取得、親を後から保存した場合の既存データ再利用。
- 平らな保存先の移行、親の変更、サムネイル維持、登録失敗時の復元、再起動。
- 通信切断の有限再試行、不完全ファイルの削除、診断から生の例外・秘密文字列を除外。
- 最上位からの折りたたみ、子孫検索、親へ戻る際の再生維持。
- ダイアログ閉鎖後の保存ゲージ、キャンセル、完了通知の5秒表示、設定の再生優先。
- 実行本体のコピー、ハッシュでの再利用確認、失敗時の原本・既存本体保持、リンク先の拒否。
- 実FFmpegのMP4/M4A stream copyで圧縮パケットのハッシュが変わらないこと。
- Windows用の4つのPE、同梱マニフェスト、リソース、起動入口とネイティブ模擬テスト。

詳細な結果・件数・ソースハッシュは配布ソースのrelease-validation/completion.jsonと各ログを参照する。Nodeの試験ではtest-isolation=noneを明示し、個々のテストが集計されることを確認する。Discord模擬通信のlocalhostだけ実行環境の通信制限を外して確認する。

## 未確認の範囲

Windows実機でのPowerShellリソース更新、タスクマネージャーの表示、GUIと長時間再生、Bilibiliの実動画・一括保存、Discordの実表示。Linuxで行うPE解析やDOMモデルの結果を、これらの実機確認として扱わない。

0.6.4のフレーム送信制御を維持したが、ネイティブクラッシュの完全解消を断定しない。保存容量は配信内容による。同じ品質を保つため追加の再圧縮を行わず、容量削減を保証しない。
