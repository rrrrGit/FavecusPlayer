## 今回の回帰テスト

| 修正点 | 確認内容 |
| --- | --- |
| パスワード入力なし | ExportとPrepareを引数なしで往復。UIの出力・取り込み呼び出しも入力引数なし。破損ZIPと旧パスワードZIPではデータを変更しない |
| 名称移行 | 保存JSON・ログイン用ファイルのバイト一致、旧フォルダーの移動、移行先の競合時に上書きしない、インストール失敗時に旧フォルダー・EXE・本体を復元 |
| Discord画像名 | 旧標準キーをfavecus_player_musicへ移行。独自キーを保持 |
| スクロール | サムネイル取得を終了しない模擬状態でも次の描画フレームで追従。曲行のDOMを作り直さない。手動操作・ドラッグ・モーダル・背景状態では追従を抑える |
| 曲送りの読み込み | 通常・前後送り・自動送りで再生画面を1つに維持。読み込みが未完了でも次のスキップを受け付け、古い失敗・終了通知を無視。読み込み中の旧音声をミュートし、音量を復元。接続準備の失敗でも再生可能。ローカルへの切り替えは画面を分離 |
| 追加先の候補 | 元のリストを非表示にし、その子は選択可能。複数の元から選んだ場合も元リストを候補から除外 |
| URL判定 | 単体・複数パート・合集・直接リストURLを分類。パート番号を保持 |
| 子リスト表示 | 曲より上に子リストの行を表示。子の曲を自動展開しない。親の再生キューは子・孫を含み、子の行からの再生・移動が可能 |
| BILI表示削除 | 番号の次がサムネイル、その次が再生ボタン。元の種類表示列を削除 |

保存・重複確認・通常／シャッフル・リピート・既存の再読み込み・音量・設定・変換・インストーラーの検証も含みます。UIはDOMモデル、Electron連携は模擬環境で確認しています。

曲切り替えではBilibiliのページ自体は読み込みます。不要なView作成をなくしたことは確認しましたが、実通信での所要時間は未計測です。添付画像だけからBilibili側の読み込み遅延の原因を断定していません。
