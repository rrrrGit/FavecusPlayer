# Favecus Player v0.7.1 の使い方

Windows x64向けの、Bilibiliと手元の動画・音楽をまとめて再生するプレイヤーです。

## インストールと更新

### はじめて使うとき

1. 配布ファイルの **Setup.exe**（名前にSetupが付いたEXE）を開きます。
2. 保存先を選びます。FavecusPlayerフォルダー自体を指定しても、同じ名前のフォルダーをさらに作りません。別の親フォルダーを指定した場合は、その中へFavecusPlayerを作ります。
3. 初回は必要な実行環境をインターネットから取得します。完了までセットアップを閉じずに待ちます。
4. **FavecusPlayer.exe**、またはデスクトップのショートカットで起動します。

### 更新するとき

1. Favecus Playerを終了します。ウィンドウの×ボタンでは終了せず、通知領域（タスクバー右下）に残ります。通知領域のアイコンを右クリックして **終了** を選んでください。
2. **Patch.exe**（名前にPatchが付いたEXE）を、更新するフォルダーの外に置いて開きます。
3. **FavecusPlayer.exe・app・runtimeがある最上位フォルダー**を選びます。例えば `D:\FavecusPlayer` です。
4. 完了後にアプリを起動します。このアプリを指すデスクトップショートカットがすでにある場合は、作成を再確認しません。

アプリ直下の標準構成は次のとおりです。

| 名前 | 内容 |
| --- | --- |
| FavecusPlayer.exe | 通常の起動用EXE |
| app | アプリ本体・操作ガイド |
| downloads | 保存した動画・音声・サムネイル |
| runtime | 実行環境、修復用EXE、起動設定、診断ログ |

修復用EXEは **runtime/config/Maintenance.exe** です。appとruntimeは動作に必要なので移動・削除しないでください。プレイリスト、設定、取り込んだローカルファイル、ログイン用データは `%APPDATA%\Favecus Player` に保存します。

FavecusPlayerの中に同名のインストールが重複している場合、プログラムだけと確認できた内側のフォルダーをruntime/previous-installationsへ保管します。保存した曲や個人ファイルがある内側のフォルダーは移動せず、完了時に案内します。個人ファイルを自動削除することはありません。

**設定 → バージョン更新** では、配信元から案内されたGoogle DriveのフォルダーURLを指定して保存します。「Google Driveを開く」でファイル名のバージョンを確認し、Patchを取得します。未設定の場合はマイドライブを開きます。更新の適用はアプリ終了後に行います。

## 親子プレイリスト

左欄の＋から、名前と親を指定してプレイリストを作れます。「最上位（親なし）」は独立したプレイリストです。既存の子を親に指定すると、孫以降も作れます。リストは合計999個、曲は保存件数の合計10000件までです。

親の選択は階層表示です。通常は最上位だけを表示し、左の矢印で親子を開閉します。検索すると一覧の構造を残したまま、一致した名前がある階層まで自動で開き、紫色で強調してその位置へスクロールします。上下ボタン、検索欄の↑／↓・Enterで複数の一致箇所を移動できます。検索だけでは親を選択しません。名前を押して選び、緑色の「選択中」に表示された階層を確認します。検索を消すと検索前の開閉状態に戻ります。

リスト名の三点メニューのすぐ右にある **＋** は、そのリストの子を作るボタンです。現在のリストが親として初期選択され、そこまでの階層を開きます。追加先画面の新規作成や、移動先の親選択にも同じ検索ツリーを使用します。

名前の右に曲数、その右に子を展開する矢印があります。曲数には子孫の曲も含めます。親を選ぶと、曲欄の上部に直属の子プレイリスト、その下に親自身の曲を表示します。子の曲を自動展開せず、プレイリスト名を押すとその中へ移動します。

曲欄の子プレイリストの右側にある矢印は、**その場で中身を展開・折りたたみ**するボタンです。展開すると子・孫のリストや曲を字下げして表示します。この矢印では再生を開始しません。開閉しても現在の曲・再生位置・次の曲は変わりません。名前を押すと、そのリストへ移動します。

子の中から1つ上へ戻る場合は、**再生リスト見出しの左の↑** を押します。親がないリストでは表示しません。現在の曲や再生順を保ったまま、表示するリストだけを親に切り替えます。

通常再生の順番は「親自身の曲 → 表示順で最初の子とその子孫 → 次の子とその子孫」です。同じプレイリストが複数箇所から参照される場合、1つのキュー内では一度だけ展開します。表示を折りたたんでいても、親の再生には子・孫以降の曲を含めます。子だけを再生する場合は名前を押してそのリストへ移動し、上部の再生を押します。展開した曲の再生・編集も可能です。並べ替えはその曲が所属するリスト内で行います。

### 並べ替えと移動

再生リスト上部の「並べ替え」から、手動順、数字→アルファベット→かな50音、曲数の多い順・少ない順、新しい要素が追加された順、作成が新しい順・古い順を選びます。全プレイリストの表示でも、親子関係を保ち、同じ階層内で並べ替えます。曲数・追加日時には子孫を含みます。古いリストに作成日時がない場合は登録順を基準にし、漢字は読み仮名を推定せず日本語の文字順にします。手動順へ戻すと元の手動配置に戻ります。

手動順を選んだ状態で、左欄の三本線をドラッグします。同じ階層の行の上端・下端に紫色の線が出ると、表示順の変更です。再起動後も保持します。三本線にフォーカスしてAlt＋↑／↓でも並べ替えできます。

別のリストの中央に緑色の枠が出る位置へドロップすると「子にしますか？」と確認します。「はい、子にする」で移動し、「いいえ」・×・Escでは変更しません。自分自身や子孫を親にする操作はできません。

リスト名横の「… → プレイリストを移動」でも、既存の親、新しい親、その親も含む新規作成、最上位への移動を選べます。移動は、それまでの最上位・親からの参照を外して新しい位置へ置きます。

親を削除しても子のデータは削除しません。削除したリストの親の同じ位置へ、子を順番どおりに引き継ぎます。最上位のリストなら、同じ最上位の位置へ子を引き継ぎます。

### ホームと全体再生

「ホーム」の文字を押すと、最上位のプレイリストを画像・リスト名・曲数のカードで表示します。画像は、そのリストの先頭の曲のサムネイルです（リスト自身に曲がなければ子孫の先頭の曲。曲がない・取得できないときは音楽アイコン）。カードにカーソルを載せると、画像の左上に「全体再生に含める」のチェック、右下に再生ボタン、右上に三点メニュー（再生・シャッフル再生・子リストを見る）が表示されます。全体再生から外したリストは、カーソルがなくてもチェックの枠が見えます。再生はそのリストと子孫を再生し、シャッフル再生は全体のシャッフル設定をオンにして、そのリストをシャッフルで再生します。画像とリスト名はリストを開き、「子リスト N ›」は直属の子のカードへ移動し、上の経路から親やホームへ戻れます。開く操作と階層移動では再生を開始しません。共有する子は各親の経路で表示し、独立した最上位として重複表示しません。

ホームの見出しと左欄の曲数は登録件数の合計です（重複登録や全体再生から外した曲も含みます）。カードの曲数には子孫を含め、共有する同じ子リストは一度だけ数えます。空のリストと全体再生から除外したリストも表示します。カードは1ページ24件までで、「前へ」「次へ」から999リストまで確認できます。長い経路は末尾3階層を表示し、省いた祖先名は「…」の補足から確認できます。ホーム上部の「全登録曲を検索」は、曲名・リスト名・所属経路・動画ID・URLを対象にします。全角/半角・英字の大小・ひらがな/カタカナをそろえて検索し、空白で区切った語はすべてに一致する登録を表示します。折り畳んだ子孫や全体再生から除外したリスト、ローカル曲も対象です。既存のリスト内検索はリストを開いて利用できます。

検索結果はサムネイル・曲名・所属経路・DL状態を1ページ50件まで表示します。同じ動画でも登録先が違えば別の行です。「▶ 再生」と曲名は、その行の所属リストと登録曲から再生します。「所属リストを開く」は再生を開始せずリストへ移動します。共有する子リスト自体の登録は一度だけ表示し、複数の親を持つ場合の経路は登録された親子順の先頭を使います。長い曲名と経路は補足から全文を確認できます。「検索を解除」または検索欄を空にすると、検索前のホームの階層・ページ・スクロール位置へ戻ります。左ツリーと曲一覧の開閉状態は保持します。

隣の▶は全体を通常再生、⤨は全体をシャッフル再生します。各リストの「全体再生」チェック、または「… → 全体再生・全体シャッフルに含める」で参加を切り替えられます。オフにしたリストと子孫は全体再生から除外します。別の有効な親からも参照する子は、その経路では対象になります。個別に選んだリストからは通常どおり再生できます。再生中の曲を全体対象から外すと全体再生を停止します。

全リスト再生では同じプレイリストの二重展開に加えて、同じ正規化URL（パート別）・同じ保存ファイルの重複登録も一度にまとめます。曲名が同じだけの別動画は別の登録として扱います。

## 曲の追加

上部は **bilibiliから検索して追加 → ファイル追加 → 既存のプレイリストから追加 → URLから追加** の順で、右寄せで配置します。

追加先のリスト名は検索できます。検索は親子関係を保ち、見つかった名前まで開きます。検索で隠れたチェックも保持します。「選択した追加先の曲を検索」で、追加先と子孫にすでに入っている曲を確認できます。

追加先はチェック式です。現在選んでいるリストが初期選択され、親・子を個別に複数選択できます。矢印で子を展開します。親にチェックしても子まで自動選択しません。

追加先欄の下には **新規プレイリストを作成** を固定表示します。名前と親を指定して作成すると、追加画面へ戻り、新しいリストが選択された状態になります。入力中のURL・選んだ曲は保持します。

### URLから追加

1. 単体動画・再生リストのURL、BV番号、av番号、共有文を貼り付けます。
2. **読み込み** を押すと種類を自動判定します。
3. 複数パートまたは合集が見つかった動画URLは、再生リストとして自動で一覧を開きます。単体動画では表示名を編集できます。**動画タイトルを取得** で取得したタイトルを入力し直せます。
4. 再生リストの場合は一覧から曲をチェックします。複数候補がある場合は、全パート・合集を切り替えられます。
5. 追加先をチェックして確定します。

単体動画は1行1件で最大100件までまとめて読み込めます。再生リストURLは1件ずつ読み込みます。共有文の追跡用パラメーターは取り除き、パート番号を保持します。b23.tvの短縮URLは通常のURLへ置き換えます。

再生リストの取得では全パート・合集・系列・收藏夹に対応します。取得できる範囲はBilibili側の公開範囲・ログイン状態によります。URLを入力しただけでは登録しません。

合集の動画一覧から「パートを開く」でその動画の全パートへ入り、「親のリストへ戻る」で兄弟の動画へ進めます。移動しても選択は保持します。取得中断・閉じるでは途中の一覧を勝手に登録しません。各動画の「追加する名前」を編集でき、空欄なら元の動画名を使います。「一覧の動画を検索」で名前・動画番号を絞れます。表示中を一括選択しても、検索で隠れた選択済みの動画は保持します。

### アプリ内のBilibili検索

右上の **設定 → bilibiliアカウント → ログイン・アカウントを開く** からログインします。未ログインの場合は検索ボタンを使えません。

検索ウィンドウでは、最小化・閉じるの左にある既存の **この動画をプレイリストに追加** を使います。表示中の動画・パートまたは対応するリストURLを「URLから追加」と同じ判定・確認画面へ渡します。動画に関連する全パート・合集も同じ流れで開けます。

ログイン状態は再生画面と共有します。検索側の音声は初期オフで、「試聴音声」で切り替えます。検索画面を隠すと検索側は一時停止してミュートになります。

### ファイル追加

動画・音楽ファイルを複数選べます。MP4、WebM、M4V、MP3、M4A、OGG、WAV、FLAC、WMAに対応します。WMAは同梱の変換環境でFLACへ変換します。複数リストへ追加しても、ファイル本体は一度だけ取り込みます。

### 既存のプレイリストから追加

ボタンの下の小さなメニューで操作を選びます。

- **既存のプレイリストから楽曲を追加**：元リストと曲を複数選び、追加先へコピーします。元の登録は残ります。**既存のプレイリストから移動** を押すと、追加先への登録後に元の登録を外します。保存に失敗した場合は元へ戻します。
- **プレイリスト単位で取り込む**：選んだリストを現在のリストの子として参照します。「取り込み元のプレイリストを削除する」がオフなら元の配置を残し、オンならその親へ移動します。リストそのものや曲のデータを消す操作ではありません。

参照したリストは同じデータです。どこから編集しても、ほかの参照箇所にも反映されます。元のリストは移動・追加先の候補から除外します。元のリストの子は個別の追加先として選べます。移動の追加先に同じURL・ファイルがある場合は既存の登録を使います。

## 重複の確認と曲名の整理

URL・ファイルの同一性と、単語に区切った曲名を比較します。「ナツノヒ」と「ナツノヒグラフ」のように、部分的に一致するだけの名前は同一扱いしません。

重複候補は最初はチェックなしです。チェックした候補だけ、重複していても追加します。追加先リストごとに確認できます。チェックしない候補は追加せず、それ以外は追加します。×・追加を取りやめるでは追加全体を中止します。

設定の **自動消去単語設定** では、登録した語句全体に一致する部分をタイトルから除去します。「ニコカラ」「純k投屏」や括弧を初期登録しています。語句を追加すると登録済みの全曲名にも適用し、再生中の音声・位置は維持します。語句を削除しても、すでに整理した曲名は元へ戻りません。

## 再生と表示

曲欄の並びは「番号 → 小サムネイル → 再生 → 曲名」です。曲名の下は **03:42 · BV番号 · P1** の形式です。1時間以上は1:23:45形式で表示します。未取得の長さは--:--で、画面に見えた曲から取得します。ローカルファイルは解析可能な形式で表示し、再生時にも更新します。

曲送りでは曲一覧を作り直さず、再生中の行の表示とスクロールだけを更新します。子を展開中なら曲の行、折りたたみ中なら子プレイリストの行を示します。サムネイル取得はスクロールを待たせません。手動スクロール中・ドラッグ中・ダイアログ表示中は自動追従を抑えます。

Bilibiliの通常の曲送りでは、同じ再生画面を使い回して切り替え時の負担を減らします。連続でスキップした場合は、前の読み込みを中断して最後に選んだ曲へ進みます。Bilibiliのロゴが出る読み込み時間は、通信やサービス側の状況によって残る場合があります。

サムネイルは表示中の行とその周辺から取得します。取得失敗時は共通アイコンです。動画のサムネイルが真っ白・真っ黒・単色に近く、何の動画か分からない場合は、動画の60秒付近の場面に置き換えて表示します（保存済み・ローカルの動画はファイルから、オンラインのBilibiliは公式のプレビュー画像から切り出します。保存データは変えません）。置き換えられないときは元の画像のままです。曲の追加・移動・再生順は変えません。

再生バーの曲名の下には「ホーム ＞ 親リスト ＞ 所属リスト」を表示します。共有リストは現在の再生元の経路を示し、移動・名前変更にも追従します。一覧と同じ「DL済み」「音声DL済み」「オンライン」のバッジで保存状態を確認でき、バッジにカーソルを合わせると保存形式と実際の再生方式を確認できます。経路が省略された場合も、カーソルを合わせると全体を確認できます。

保存済みの動画やローカルのファイルを動画モードで再生するときは、ブラウザー標準ではなくアプリ独自の操作が動画の下に出ます（カーソルを動かすと表示し、しばらく動かさないと隠れます）。再生・一時停止、再生位置、右端の拡大ボタンがあり、動画をクリックすると再生・一時停止、ダブルクリックで拡大します。保存済みの動画では、右下に保存済みの画質（例：720p）が表示され、押すと **別の画質で保存し直す…** から既存の保存画面を開けます。切り替えは再保存で行い、新しい画質は保存が終わった次の再生から使います（再生中のファイルは保持され、後で整理されます）。音量は下の再生バーで調整します。標準の操作にあった「ダウンロード」「再生速度」「ピクチャーインピクチャー」のメニューはありません。

Bilibiliのオンライン再生は、Bilibili自身のプレイヤーの操作を使います（画質もBilibili側の設定です）。下の再生バーの拡大ボタンと、Bilibili自身の全画面ボタンのどちらでも、動画がウィンドウ全体に広がります。**Esc** で元の大きさに戻ります。画面を開いたとき・曲モードへの切り替え・停止・ウィンドウを隠したときも、拡大は解除されます。

曲／動画ボタンでサムネイル表示と動画表示を切り替えます。音声と再生位置は維持します。オンライン動画は初期画質360pを指定し、画質メニューが後から表示された場合も初回だけ選びます。手動で選んだ画質は上書きしません。保存済みの動画は保存した画質で再生します。

読み込みが12秒進まない場合、または再生中の位置が15秒進まない場合は、アプリ内で公式プレイヤー部分を表示する方式へ切り替えます。ブラウザーは開きません。位置を保持して復旧し、さらに失敗した場合は1回だけ再作成します。最後の復旧にも失敗したらプレイヤーを閉じて負荷を解放します。曲の選択とキューは残り、再読み込み・次の曲を操作できます。破棄済みの画面から届く通知や操作を遮断し、同じ警告の連続表示を抑えます。成功した動画・同じ合集の情報が取得できた場合は、同じ起動中にその方式を優先します。一時停止や再生終了を停止故障として扱いません。

「公式ページ表示」は公式ページ全体を明示的に開く別の操作です。再読み込みは選択中の表示方式と再生位置を保ちます。通信・認証・地域・投稿者の制限やサイト構造の変更によっては復旧できません。警告が出た場合の確認方法は、このガイド末尾の「エラーが出たとき」を参照してください。

再生／一時停止、前後の曲、10秒移動、シーク、停止、音量、ミュートに対応します。新しい曲は先頭から開始します。ローカルの不足ファイルやBilibili側の非公開・制限はアプリでは解除できません。

### シャッフルとリピート

通常の曲選択では選択曲を先頭にし、残りをシャッフルします。⤨シャッフル再生ボタンは履歴をリセットし、1曲目から抽選し直します。親リストは子孫まで展開した全曲が対象です。

初期設定では再生回数の少ない曲を優先して抽選します。実際に3秒以上再生が進むと1回として記録し、通常再生の回数も含めます。3秒未満の短い曲は、ほぼ全体を再生して終了した場合に記録します。読み込み失敗・位置移動・短いスキップだけでは加算しません。同じ正規化URLとパート、または同じ取り込みファイルは、複数リスト間でも同じ回数を使います。

重みは `1 / (1 + 再生回数)` です。よく再生した曲ほど後ろに出やすくなりますが、完全に回数順へ固定するものではありません。1周内の曲は重複させず、表示した予定はその周の途中で再抽選しません。

「設定 → シャッフルの再生回数」で優先機能をオフにしたり、記録をリセットできます。記録はアプリ終了後も保持します。リセットは次回のシャッフル開始へ反映し、現在の予定は変えません。プレイリストZIPへ再生回数を含めません。プレイリストの同期を有効にしている場合は、再生回数と「再生回数が少ない曲を優先する」の設定が、同じアカウントのiPhone版とも共通になります（接続先のSupabaseで schema.sql をもう一度実行しておく必要があります。ローカルの曲の回数は、この端末だけです）。

全曲リピートでは一周の最後の曲を次の周の候補から除き、残りを再シャッフルします。除外はその周だけです。1曲しかない場合は同じ曲を繰り返します。1曲リピートや「前の曲」での再再生は別扱いです。下部の次曲表示には実際に確定した次の曲を表示します。

通常再生・シャッフル中の **次に再生** の横には、次の曲の所属プレイリストを `EroGameSongs/ケロQ・枕/サクラノ刻` のように表示します。「最上位（親なし）」や「マイライブラリ」は含めず、実際の最上位プレイリストからの名前をつなぎます。既存の曲番号と曲名はその下に残します。複数の親から共有するリストは、再生を開始した範囲を通る階層を優先し、全リスト再生では表示順で最初の経路を使います。

「次に再生」をクリックすると、直後の3曲が見える高さに開きます。上へスクロールすると再生済みの曲、下へスクロールすると確定済みの予定を曲名で確認できます。曲名を押しても再生しません。履歴は現在のキュー内で実際に移動した直近1000件です。新しく再生を開始・停止するとリセットします。リピート時は少なくとも次の3曲まで予定を確定します。

### 再生中の曲へ自動スクロール

通常再生・シャッフルともに曲が切り替わると、表示中の一覧内で再生中の行を先頭へ合わせます。曲の並び順は変更しません。

前面表示中のみ動作します。手動スクロール中・直後、スクロールバー操作中、曲の並べ替え中、モーダル表示中は自動移動を控えます。検索で隠れている行や表示外の別リストへ、勝手に切り替えません。

再生・シャッフル再生・前後送りのボタンを押した場合は、直前の手動スクロールによる待機を解除して追従します。一覧から動画へフォーカスが移っても一覧は操作でき、曲送りのたびに動画画面をクリックし直す必要はありません。最小化・背面表示中の自動追従は抑えます。

## 曲の検索とドラッグ

「リスト内を検索」は、表示中の親リストだけでなく、折りたたまれた子・孫の曲名と動画番号も対象です。一致する階層を開いて表示し、検索を消すと元の開閉状態に戻します。

曲番号をドラッグして並べ替えている間も、ホイールで上下へスクロールできます。リストの端に寄せる自動スクロールも使えます。同じリストの曲へ落とすと並べ替えます。

別プレイリストへ落とすと、「追加（元にも残す）」「移動」「キャンセル」を選びます。リストの見出しなら末尾へ入れます。展開した別リストの曲の上半分・下半分へ合わせると紫色の挿入線が出て、確認画面に示された曲の前・後へ入れます。確認前には変更しません。見出しへの追加は通常の重複確認を使います。位置を指定した場合、同じ曲があればその既存の行を指定位置へ動かし、重複登録しません。移動では元の行を取り除きます。

## 楽曲のダウンロード方法

### 保存する操作

1. 左下の **動画・音声の保存**、またはプレイリストの **… → このプレイリストの動画・音声を保存** を開きます。
2. 上部で保存するプレイリストを選びます。名前を検索すると、該当リストがある階層まで開きます。検索だけでは対象を変更しないので、名前を押して「選択中」の表示を確認します。
3. 子や孫のリストもまとめる場合は **子プレイリストも含める** をオンにします。同じ動画の同じパートは一度だけ保存し、「ファイル追加」で取り込んだローカルファイルはダウンロードの対象にしません。
4. **動画（MP4）** または **音声のみ（M4A）** を選びます。動画の標準画質は720pです。容量を抑えるなら360p、大きく表示するなら1080pを選べます。配信元に指定画質がない場合は、利用できる候補から選びます。
5. 容量・時間の確認が終わっていなくても保存を開始できます。**追加の保存容量**、一時ファイルを含む **必要空き容量**、**完了までの目安** を表示します。対象や形式を変えると再計算します。取得できない曲がある場合は、その分を「未確定」と表示します。
6. 保存先を確認します。標準はアプリの **downloads** です。「保存先を変更」で別のフォルダーを選べます。既存データは自動移動しないため、以前の保存先を使うときはそのフォルダーを再選択してください。
7. **保存を開始** を押します。画面が閉じ、左下の保存ボタンの上に進捗ゲージと **キャンセル** を表示します。最大3曲を同時に処理します。確認中に開始した場合は、保存で取得した配信情報から未確認の曲を含む全体の容量を推計し、確認済み件数とともに更新します。各曲の保存前にも空き容量を確認します。保存画面を開き直すと曲ごとの状態、全体の取得量、経過時間、残り時間を確認できます。開始前の時間は回線速度10〜100 Mbpsを仮定した範囲で、開始後は実際の進捗から更新します。未確認の曲が多い間は推計の幅が大きく、通信・動画の長さ・端末の速度で変わります。
8. 完了すると **保存が終了しました。** と表示し、約5秒後にゲージを隠します。失敗や中止があった場合はその結果を示します。通常どおり再生すると、**設定 → 再生・表示 → 再生するデータの優先** で選んだ方式を使います。「保存済みの動画・音声を優先」なら、曲モードでは音声、動画モードでは動画を優先し、片方だけなら利用できる形式を使います。設定変更は次の曲の読み込みから反映します。

画面を閉じても保存は続きます。左下の「キャンセル」、保存画面の「保存を中止」、またはアプリ終了で中断できます。完了したデータは残り、途中のファイルを完成済みとして扱いません。同じ形式・同じ指定画質で保存済みの曲はスキップします。再開すると未保存の曲から処理し、サムネイルだけ不足している曲は画像を補います。通信の切断・不完全な転送は回数を限って再取得します。認証・利用制限・空き容量不足では連続して取得を繰り返しません。

元のオンライン動画を再生したい場合は、プレイヤーの **オンラインで再生** を使います。認証が必要な動画は設定からBilibiliへログインして保存します。公開範囲・利用制限・保護のある配信では保存できない場合があります。失敗した曲と理由は保存画面に表示します。

追加の再圧縮をしないため、同じ品質を維持したまま必ず小さくなるわけではありません。容量を抑える選択肢は音声のみ、または低い動画画質です。容量削減のために選択した画質をさらに引き下げる処理は行いません。

### アプリの中で行う保存処理

- **ステップ1：対象を整理する。** 選択したリストから動画URLとパート番号を集め、重複をまとめて保存済みか確認します。
- **ステップ2：配信情報を確認する。** Bilibiliから対象パートの情報を取得し、保存可能な映像・音声を選びます。確認中に保存を開始した場合は、この情報を全体の容量・時間の推計にも使い、曲の取得と並行して表示を更新します。映像は互換性の高いH.264、音声はAACを使います。音声は原則として192 kbps以下で最良の候補を選び、候補がそれ以上だけの場合は最も小さいものを使います。
- **ステップ3：一時ファイルへ取得する。** 映像と音声が別の場合はそれぞれ取得します。取得途中のデータはdownloads内の作業フォルダーに置きます。
- **ステップ4：再圧縮せず形式を整える。** 映像と音声をMP4へまとめるか、音声をM4Aへ保存します。基本的に配信済みのデータをそのまま使用し、追加の圧縮による品質低下を避けます。
- **ステップ5：完成したデータを確認する。** 空のファイルや不完全な出力を完成済みにせず、確認できたものを曲ごとのフォルダーへ置きます。
- **ステップ6：サムネイルを保存する。** 同じ曲のフォルダーへ画像も保存します。画像だけ取得できなかった場合は、動画・音声を保持して結果に表示します。
- **ステップ7：プレイリストとの対応を記録する。** 元のURLと保存ファイルをdownloads/index.jsonへ記録し、再生時に見つけられるようにします。最後に不要な一時ファイルを片付けます。

### 保存先の整理

標準の配置は **downloads → media → 動画識別子・パート → 動画・音声・サムネイル** です。曲ごとのフォルダーを保ち、動画と音声は同じ曲のフォルダーを使います。同じ動画・パートを複数リストへ登録しても保存データを共用し、別のパートは別曲として管理します。曲名やプレイリスト名・所属先の変更では保存場所を動かしません。

以前のプレイリスト別の保存データは、起動時などに管理情報と実体を確認して再ダウンロードせず移行します。新しい保存先と管理情報の確定後に旧ファイルを整理し、失敗した場合は元データを保護して再開します。復旧処理が終わるまで、旧フォルダーやバックアップを手動で削除しないでください。

曲やプレイリストを削除しても、ほかのリストに参照が残る保存データは保持します。最後の参照がなくなったデータだけを整理し、再生・ダウンロード・出力で使用中なら終了後に再確認します。アプリが管理しないファイルを一律削除する機能ではありません。画質を変えて再保存した場合は、新しいデータの保存と登録が成功した後に、同じ形式の古いデータを片付けます。

**index.jsonと曲のフォルダーは一緒に保管してください。** エクスプローラーで曲ファイルだけを移動・改名すると、プレイヤーから見つけられなくなります。別のPCへ移す場合は、次の「プレイリストの出力と取り込み」を使うと、対応関係も一緒に移せます。

## キーコンフィグ

アプリが前面にあり、通常ウィンドウが表示されているときだけ次のキーが動作します。動画側へフォーカスがある場合も共通です。最小化・背面・タスクバー埋め込み中、文字入力中、設定や確認画面では動作しません。

| 初期キー | 操作 |
| --- | --- |
| → / ← | 10秒進む / 10秒戻る |
| ↑ / ↓ | 音量を2ポイント上げる / 下げる |
| Space | 再生・一時停止 |
| Shift + → / Shift + ← | 次の曲 / 前の曲 |

「設定 → キーコンフィグ」で欄を選んでキーを押し、保存します。同じ組み合わせの重複登録はできません。Backspace・Deleteは解除、初期設定に戻すボタンで全操作を戻せます。次曲・前曲・再生切り替えは押しっぱなしで連続実行しません。音量と10秒移動は長押しで繰り返します。

## 設定

設定は右上の **⚙ 設定 · Discord接続状態** から開きます。接続済みの場合は緑の点を表示します。

設定の順番は **音量 → bilibiliアカウント → プレイリストの出力 → 使い方 → 自動消去単語設定 → Discordアクティビティ → ミニプレイヤー、タスクバー → 再生・表示 → キーコンフィグ → シャッフルの再生回数 → バージョン更新** です。

詳細設定は左上に戻る、右上に×があります。Discord・タスクバー・自動切り替えの設定は「保存して戻る」または「戻る」で保存します。音量、削除語句、左欄の幅は変更時にすぐ保存します。

**再生・表示 → プレイリスト欄の幅** で左欄の幅を170〜400に変更できます。再起動後も維持します。

バックグラウンド中の自動曲モードは初期値5分です。時間変更・無効化ができます。動画へ戻すときは読み込み済みの同じ再生画面を再表示・再描画します。

使い方はアプリ内の別ウィンドウで開きます。外部ブラウザーは起動しません。設定やダイアログの背面にある曲名・リスト名は操作とツールチップの対象から外します。

## プレイリストの出力と取り込み

**設定 → プレイリストの出力** を開きます。

**出力・取り込みのどちらもパスワード入力は不要です。** 出力は2つのボタンから選びます。

- **プレイリスト情報のみ出力**：主にPC・スマホ間での共有用です。JSON（標準）またはZIPへ、リスト名・親子関係・並び順・曲名・動画リンク・パート番号・識別情報などを保存します。動画・音声・DLサムネイルは同梱しません。ローカル曲は登録情報を残し、実ファイル未同梱として扱います。スマホ版アプリ自体はまだ含みません。
- **DLデータを含めて出力**：主にPC間での共有用です。上記の情報と、保存済みの動画・音声・サムネイル、取り込んだローカルファイルをZIPへまとめます。未保存の曲はリンクを保持し、ローカルファイルの不足は件数で案内します。

「JSON・ZIPを取り込む」から情報のみのJSON/ZIP・DLデータ付きZIPを選びます。ZIPの手動展開は不要です。

1. **取り込み先の親** を選びます。「最上位（親なし）」なら最上位へ復元し、既存リストを選ぶとその下へ元の階層をまとめて入れます。名前を検索して位置を確認し、名前を押して選びます。
2. **取り込むリスト** にチェックを付けます。最初は未選択で折りたたんで表示します。矢印で子・孫を開き、名前で検索できます。検索で隠れた選択も保持します。親のチェックで子孫もまとめて選びます。
3. 子のチェックを外すと親の一括選択を解除し、残った選択に必要な祖先だけを空のプレイリストとして維持します。祖先自身や未選択の兄弟の曲は含めません。
4. **選択したリストを取り込む** を押します。全件なら **すべて取り込む** を押します。検索で隠れたリストも含め、すべてを元の関係のまま取り込みます。「すべて選択」「選択を解除」でチェックだけを変更することもできます。
5. 完了後は取り込んだリストへ移動します。

どちらの出力でも、親子関係と順序を保って取り込みます。共有用の形式なので、受け取った人はパスワードなしで内容を読み込めます。

取り込み画面には、リストごとの保存済みデータ件数も表示します。**選んだプレイリストとその子孫の曲に対応するメディアだけ**を取り込みます。両方の形式が同梱されていれば動画と音声を復元します。未選択リストだけで使うファイルは取り込みません。同じ保存データがすでにあれば重複コピーを省きます。

子だけを選んでも元の祖先を構造として残し、取り込み先の親へ接続します。例えば元がA → B → Cのとき、Cだけを保存先Dへ取り込むとD → A → B → Cになります。AとBは空の容器とし、Cの曲と子孫を取り込みます。保存済みのメディア・画像は、動画リンク・パート単位の共通配置へ復元します。元のファイルに親子関係が残っていない場合は自動で復元できません。同名の既存リストは上書きせず、「取り込み1」などを付けた別リストとして追加します。一覧で同名の有無も確認できます。

旧JSON形式のプレイリストも選択取り込みできます。ファイル名が旧名称のままでも読み込めます。同梱mediaフォルダーはJSONの隣に置きます。

パスワード付きの旧アーカイブは、この画面では取り込めません。元のプレイリストを開ける環境で、パスワード不要のZIPへ出力し直します。

大きなデータにはZIP64を使用します。出力先・取り込み先の空き容量を確保してください。見つからないローカルファイルは結果に件数を表示します。ログイン情報・DiscordのID・音量・再生回数など、アプリ全体の設定は出力に含めません。

## プレイリストの同期とiPhone版

プレイリストの構成と曲の登録情報を、複数の端末（Windows版・iPhone版）で同期できます。使わない場合は、何も設定しなくてかまいません。

**設定 → プレイリストの同期** を開き、上から順に進めます。

1. **接続先**：自分で用意したSupabaseプロジェクトのProject URLと、公開してよいanon（publishable）キーを入力して保存します。service_role・secretキーは使えません。
2. **サインイン**：メールアドレスを入力して「コードを送る」を押し、届いた数字を入力して「サインイン」を押します。
3. **同期**：「同期を有効にする」を押します。有効にする前に、現在のプレイリストのバックアップをデータフォルダーへ残します。以後は、変更したあとと一定の間隔で自動的に同期します。「今すぐ同期」でいつでも実行できます。

- **同期するもの**：リストの階層・名前・並び順、曲の登録情報（曲名・動画リンクなど）。**同期しないもの**：曲のファイル・保存した動画や音声・ログイン情報・パスワード・ファイルの場所。
- 同期を止めても、プレイリストは消えません。つながらないときの変更は端末に保持し、つながると自動で再試行します。
- 別の端末で同時に変更した場合は、項目ごとに新しい方を採用します。削除は一定期間（90日）保持してから整理します。
- 同期を「停止しています」と表示したときは、サーバーの内容と、この端末の内容のどちらが正かを確認するためです。**サーバーの内容で復元**または**この端末の内容を正とする**のどちらかを選ぶまで、何も上書きしません。

iPhone版は個人利用向けで、AltStoreで導入します。曲のファイルは同期されないため、iPhone版にメディアを移すときは、**プレイリストの出力**のDLデータ付きZIPを、iPhoneの「ファイル」アプリから取り込みます。iPhone版から出力したZIPも、Windows版の「JSON・ZIPを取り込む」で読み込めます。

## ミニプレイヤーとDiscord

ウィンドウの×ボタンを押すと、アプリは終了せず通知領域（タスクバー右下）へ格納され、再生は続きます。通知は表示しません。通知領域のアイコンをダブルクリックすると元の画面に戻り、クリックでミニプレイヤー、右クリックのメニューで再生操作と **終了** を選べます。Windowsのシャットダウン・ログオフ時と、通知領域のアイコンを作成できなかったときは、×ボタンで通常どおり終了します。

右上の下向き矢印でミニプレイヤーへ切り替えます。Windowsのタスクバー埋め込みは試験的な機能です。接続できない場合は独立した小型画面へ戻します。埋め込み状態では右端の拡大ボタンだけが通常ウィンドウを開きます。音量の操作や曲名クリックでは開きません。

**設定 → Discordアクティビティ** でApplication IDと画像名を指定し、有効にします。画像名の初期値は **favecus_player_music** です。Discord Developer PortalのArt Assetsにも同じ名前で画像を登録します。詳細は[Discordの設定手順](DISCORD.html)を参照してください。

「楽曲アイコンのサイズ」は **小：補助画像** と **大：メイン画像** から選べます。小ではアプリアイコンを大きく表示し、大では楽曲画像を大きく、アプリアイコンを補助表示します。Discordに登録したアプリ自体のアイコンは変更しません。位置・細かな大きさ・背景全体はDiscord側で決まり、四隅の自由指定には対応していません。

「楽曲アイコンを押すと動画を開く」がオンの場合、楽曲画像だけに選択中のパートの動画リンクを設定します。曲名やアプリアイコンには動画リンクを付けません。Discordが独自に表示するアプリ情報画面や、リンクを開く確認画面の動作はDiscord側の設定によります。

サムネイルを非表示にすることも、一時停止中のアクティビティを非表示にすることもできます。非表示にしない場合、一時停止位置を文字で表示します。

詳しくは[タスクバーの使い方](TASKBAR.html)も参照してください。

## エラーが出たとき

1. 警告に表示された **エラーコード** と **記録ID** を控えます。警告画面のスクリーンショットでも確認できます。
2. アプリの **runtime/logs** を開きます。起動・異常終了の記録は **launcher.log**、曲切り替えや読み込み・復旧の記録は **player-diagnostics.jsonl** です。同じ記録IDで対応する起動回を探せます。保存の失敗は保存画面に **FP-DOWNLOAD-…** と記録IDを表示し、**download-diagnostics.jsonl** に原因の分類・処理段階・HTTP状態を残します。実行基盤の記録は **electron.log**、異常終了の詳細ファイルは **crashes** フォルダーです。これらは端末内に保存され、自動送信されません。
3. 再生できない曲では「再読み込み」や「次の曲」を使えます。保存済みデータの問題か切り分ける場合は「オンラインで再生」を使います。
4. 必要なファイルが欠けている場合は、アプリを終了して **runtime/config/Maintenance.exe** を実行します。

| エラーコードの先頭 | 確認する箇所 |
| --- | --- |
| FP-LAUNCH | Windowsがアプリのプロセスを開始できなかった記録 |
| FP-EXIT | 起動したアプリが異常終了した記録 |
| FP-EXIT-80000003 | 実行環境の内部停止。同じ記録IDのログとcrashes内の記録をまとめて確認する |
| FP-EXIT-FFFF7003 | クラッシュ記録機構に接続されていない状態での異常終了。元の原因はこのコードだけでは確定できない |
| FP-PLAYER-LOAD-ERROR / NAVIGATION-ERROR | 再生ページの読み込み |
| FP-PLAYER-RENDERER-EXITED | 再生画面のプロセス終了 |
| FP-PLAYER-RECOVERY-EXHAUSTED | 自動復旧を試しても再開できなかった状態 |

コードは原因を調べる手掛かりです。コードだけで一つの原因に決まらない場合は、同じ記録IDのログから直前の操作と終了状況を確認します。
